# AGENTS.md

Rules for any coding agent (human or AI) working in this repository. Summarised from
`file-manager-coding-agent-spec.md` §35; that document is authoritative if this summary drifts.

## Before changing anything

- Inspect existing repository conventions before changing architecture.
- Depended-on tasks in `TASKS/` establish contracts (types, module boundaries) — read them before
  guessing at an interface.

## While working

- Prefer small, reviewable commits.
- Avoid speculative abstractions that aren't linked to a planned feature.
- Include tests with each behaviour change.
- Avoid unsafe filesystem assumptions; never test destructive operations outside temporary test
  roots.
- Use strongly typed errors (`thiserror` in libraries, `anyhow` only in `apps/*` binaries).
- Add cancellation to long-running work.
- Preserve browser (Axum) and Tauri parity — don't build a feature that only works in one host.
- Document public interfaces.
- Keep generated code (OpenAPI document, Orval client) clearly separated and never hand-edited.

## Before finishing

- Run formatting, linting and relevant tests (`pnpm run lint`, `pnpm test`) before declaring a task
  done.
- Report incomplete or platform-untested behaviour explicitly in the task's Agent Notes — never
  silently.

## Must not

- Move application logic into Mithril components.
- Make Axum or Tauri commands the core application architecture — both are thin adapters over
  `fm-application`.
- Expose arbitrary filesystem methods, unrestricted plugin APIs, or native Rust dynamic libraries
  as the plugin ABI, directly to JavaScript/plugins.
- Recursively copy files in TypeScript (that belongs in the Rust operation engine).
- Render large directories without virtualization.
- Silently overwrite user files or silently follow symbolic links.
- Add React/Vue/Svelte/Angular-specific libraries, or a generic state framework without a
  demonstrated need.
- Rely solely on browser mode without testing Tauri regularly.

## Generated code

- `frontend/openapi/openapi.json` is generated by `pnpm run api:export` (`fm-server export-openapi`)
  and checked into git.
- The Orval-generated Fetch client under `frontend/src/api/` is generated by
  `pnpm run api:generate` and checked into git. Do not hand-edit either — regenerate them instead.
- `pnpm run api:check` fails CI when either is stale relative to the backend.
